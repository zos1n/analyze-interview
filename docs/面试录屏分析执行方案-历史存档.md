# 面试录屏最低成本分析执行方案（历史存档）

> 本文件为早期面试录屏分析首次执行方案的历史存档。
> 当前最新版本请参考 `docs/面试录屏分析工具规范.md` (v2.1)。

## 一、目标

以最低云端费用和最低 Token 消耗分析面试录屏，只使用音频内容：

```text
录屏音轨检查
→ 保留原始音轨并生成 ASR 单声道副本
→ Whisper Small 本地全量粗转
→ 本地生成问题索引
→ Whisper Large V3 Turbo 局部精转
→ 低成本文本模型分析关键问答
```

禁止将视频、音频或完整转写上传至云端服务。MLX Whisper 作为本地 ASR，可以读取本地音频。

## 二、执行边界

### 输入

- 用户提供录屏的绝对路径。
- 执行前必须获得用户对该录屏的明确读取授权。

### 产物目录

```text
<视频所在目录>/<视频文件名去掉扩展名>_analysis/
```

若视频目录不可写，立即停止并报告，不得自行改换目录。

### 固定产物

```text
<video_stem>_analysis/
├── .venv/
├── source-info.json
├── audio-source.flac
├── audio-asr.flac
├── transcript-full.json
├── transcript-full.srt
├── question-index.md
├── selected-segments.json
├── transcript-key.md
├── interview-review.md
├── execution-state.json
└── execution-log.txt
```

### 禁止事项

- 不覆盖、修改或删除原视频。
- 不自动删除任何中间产物。
- 不修改 `.env`、密钥、Token、证书或项目配置。
- 不创建视频、音频或转写稿的公网链接。
- 不使用云端视频理解、云端 ASR 或说话人声纹服务。
- 不把完整转写稿提交给文本分析模型。
- 不从来源不明的位置下载 FFmpeg 或模型文件。

## 三、已知执行环境

```text
OS: macOS
Architecture: Apple Silicon arm64
Homebrew: /opt/homebrew/bin/brew
Python: 3.9.6
FFmpeg: 未安装
FFprobe: 未安装
```

`mlx-whisper` 固定使用 `0.4.3`。

## 四、环境检查与审批门

执行前依次检查：

1. 视频路径存在且可读。
2. 视频目录可写。
3. 视频包含至少一条有效音轨。
4. 剩余磁盘空间不少于 5GB。
5. Homebrew、Python、FFmpeg 和 FFprobe 的实际状态。

以下操作必须先获得用户明确批准：

- 使用 Homebrew 安装 FFmpeg。
- 创建 Python 虚拟环境并安装依赖。
- 从 Hugging Face 下载 Whisper 模型。

批准后安装 FFmpeg：

```bash
/opt/homebrew/bin/brew install ffmpeg
```

创建隔离环境并安装固定版本：

```bash
python3 -m venv "$OUTPUT_DIR/.venv"
"$OUTPUT_DIR/.venv/bin/pip" install "mlx-whisper==0.4.3"
```

安装完成后，将以下实际版本写入 `execution-log.txt`：

- macOS 与 CPU 架构
- Python
- FFmpeg / FFprobe
- mlx-whisper
- MLX
- 使用的模型 revision

安装或下载失败时停止，不得自动切换云端方案。

## 五、音轨检查与提取

### 1. 检查全部音轨

使用 FFprobe 记录：

- 视频总时长；
- 全部音轨索引；
- 默认音轨；
- 编码格式；
- 采样率；
- 声道数；
- 各音轨时长。

结果写入 `source-info.json`。

### 2. 音轨选择规则

- 只有一条音轨时，使用该音轨。
- 多音轨时，优先使用标记为 `default` 的音轨。
- 没有默认音轨时，使用第一条音轨。
- 不自动混合多条独立音轨。
- 左右声道可能分别包含面试官和候选人时，必须保留原始声道信息，禁止只保留单声道产物。

### 3. 保留原始声道副本

```bash
ffmpeg -i "$VIDEO_PATH" \
  -map 0:a:<selected> \
  -c:a flac \
  "$OUTPUT_DIR/audio-source.flac"
```

若左右声道明显来自不同声源，额外输出：

```text
audio-left.flac
audio-right.flac
```

### 4. 生成 ASR 单声道副本

```bash
ffmpeg -i "$OUTPUT_DIR/audio-source.flac" \
  -ac 1 \
  -ar 16000 \
  -c:a flac \
  "$OUTPUT_DIR/audio-asr.flac"
```

### 5. 音频验收

- 文件非空且可完整解码。
- 音频时长不得超过视频时长 2 秒。
- 音频比视频短超过 5 秒时记录警告，但不直接判定失败。
- 发现无音轨、损坏或解码失败时立即停止。

## 六、本地转写模型

### 全量粗转

```text
mlx-community/whisper-small-mlx
```

### 关键片段精转

```text
mlx-community/whisper-large-v3-turbo
```

首次下载后，将 Hugging Face 实际解析出的 revision 或 commit 写入 `execution-log.txt`。恢复执行时必须复用同一 revision。

固定专业词表：

```text
AI Coding
Claude Code
Agent
Planner
Reviewer
Hooks
Skills
Subagent
React
SSE
RAG
Node.js
TypeScript
Webpack
Vite
```

专业词表只用于帮助识别，不得加入对面试答案的猜测。

## 七、全量粗转

固定参数：

- `language=zh`
- `task=transcribe`
- 使用片段级时间戳
- 不启用逐词时间戳
- 不翻译
- 不润色
- 不根据上下文补写听不清内容

输出：

```text
transcript-full.json
transcript-full.srt
```

超过 3 小时的音频按连续 30 分钟逻辑区间处理，不物理切割原始音频。相邻区间保留 5 秒重叠，合并时按时间戳和文本相似度去重。

每完成一个区间，更新 `execution-state.json`。恢复执行时跳过已经完成且校验通过的区间。

## 八、本地问题索引

使用确定性脚本处理粗转结果，不调用 LLM。

### 候选区间规则

1. 命中以下技术与经历关键词：
   - AI、Coding、工作流、Agent、Planner、Reviewer、Hook、Skill、Subagent
   - 项目、负责、主导、难点、指标、收益、架构、方案
2. 命中问句表达：
   - 为什么
   - 怎么
   - 如何
   - 有没有
   - 介绍一下
   - 具体说说
3. 命中 `[听不清]`、明显重复或长停顿附近。
4. 必须包含面试开头、反问环节和结束前 5 分钟。
5. 每个命中区间前后扩展 90 秒。
6. 合并重叠区间。

输出 `question-index.md`，内容包含：

- 候选区间编号；
- 开始与结束时间；
- 命中原因；
- 对应粗转文本。

若候选区间超过总时长的 40%，停止自动精转，先让用户根据问题索引选择区间。禁止直接对全量音频使用 Turbo。

## 九、关键片段精转

- 只处理用户确认或规则选中的区间。
- AI Coding 与项目经历相关区间必须精转。
- 使用 `clip_timestamps`。
- 启用逐词时间戳。
- 禁止对完整音频运行 Turbo。
- 不进行声纹识别。

说话人标注规则：

- 原录屏存在独立声道时，可以结合声道来源标注。
- 没有独立声道时，先标注为“说话人 A / B”。
- 只有问答关系明确时，才改为“面试官 / 候选人”。
- 无法确认时必须保留 `[说话人不确定]`。
- 听不清内容标记 `[听不清]`，不得补写。
- 专业词无法确认时标记 `[术语不确定：候选词]`。

输出 `transcript-key.md`：

```md
## 问题 1：问题主题

时间：00:00:00 - 00:00:00

面试官 / 说话人 A：
忠实原话

候选人 / 说话人 B：
忠实原话

追问：
忠实原话

客观现场信号：
仅记录打断、停顿、重复确认、立即跳题等可观察事实。
```

## 十、转写质量校验

必须抽检：

- 开头 60 秒；
- 中间 60 秒；
- 结尾 60 秒；
- AI Coding 全部关键问答；
- 项目经历全部关键问答。

检查：

- 时间戳是否连续；
- 重叠区间是否正确去重；
- 是否存在静音幻觉；
- 是否出现重复循环；
- 技术词是否明显误识别；
- 是否擅自补全听不清内容。

发现错误时只重转对应区间，不重新运行全量转写。

最终分析引用的原话必须来自 Turbo 精转结果，并包含时间戳。

## 十一、最低 Token 分析

### 模型

```text
model: gpt-5.4-mini
reasoning effort: low
```

若执行环境没有该模型，停止并让用户选择替代模型，不得自行切换。

### 输入限制

- 分析模型只允许读取 `transcript-key.md`。
- 禁止读取原视频、音频和完整转写稿。
- 按完整问答边界拆分，禁止机械截断一句回答。
- 单个主题输入超过约 8,000 Token 时继续拆分。

### 分析顺序

1. AI Coding 工作流；
2. 项目经历；
3. 面试官现场信号；
4. 综合判断。

综合判断阶段只输入各主题结论、置信度和必要原话，不重复提交全部关键转写。

### 固定分析结构

每道题必须输出：

1. 面试官的考察目标；
2. 回答覆盖的内容；
3. 缺失内容与风险；
4. 打断、追问和跳题等客观信号；
5. 判断为明确失分、隐性失分或无明显问题；
6. 更好的真实回答结构；
7. 对最终结果的影响及置信度。

禁止：

- 根据“没有追问”直接判断回答正确或高分；
- 把候选人的主观感受当作面试官评价；
- 把单个问题直接认定为淘汰原因；
- 没有证据时猜测面试官态度；
- 为了完整而虚构现场细节。

## 十二、断点恢复与失败处理

`execution-state.json` 至少记录：

```json
{
  "video_path": "",
  "output_dir": "",
  "selected_audio_track": null,
  "current_stage": "",
  "completed_ranges": [],
  "small_model_revision": "",
  "turbo_model_revision": "",
  "artifacts": {},
  "last_error": null
}
```

规则：

- 已存在且校验通过的产物直接复用。
- 任一步失败后停止并记录错误。
- 不删除中间产物。
- 不覆盖已经校验通过的文件。
- 不从头重复执行已经完成的区间。
- 不因本地模型失败而自动切换云端服务。

## 十三、最终验收标准

- [ ] 原视频内容、哈希和修改时间保持不变。
- [ ] 视频路径和读取授权已确认。
- [ ] 环境、安装和模型下载均经过审批。
- [ ] 全部音轨及声道信息已有记录。
- [ ] 原始声道信息没有被不可逆丢弃。
- [ ] ASR 音频非空且可完整解码。
- [ ] 完整转写只保存在本地。
- [ ] AI Coding 问答已经过 Turbo 精转。
- [ ] 项目经历问答已经过 Turbo 精转。
- [ ] 所有引用原话都包含时间戳。
- [ ] 听不清和说话人不确定内容没有被补写。
- [ ] 依赖版本及模型 revision 可追溯。
- [ ] 分析模型只接收关键片段。
- [ ] 分析结论区分事实、推断和无法判断。
- [ ] 全流程没有产生云端视频理解或 ASR 费用。

## 十四、严格执行指令

执行 Agent 必须遵守：

1. 当前第一步只读取本方案和检查用户提供的录屏元信息。
2. 未获得录屏读取授权前，不访问录屏。
3. 未获得安装批准前，不安装 FFmpeg、Python 包或下载模型。
4. 每完成一个阶段，先验证产物再进入下一阶段。
5. 遇到本方案未覆盖且会影响结果的情况，停止并向用户报告，不自行扩展方案。
6. 不读取与录屏分析无关的文件。
7. 不执行删除、覆盖、上传或公开发布操作。
