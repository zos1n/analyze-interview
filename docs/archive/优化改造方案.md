## 二、详细技术改造规约

### 1. `audio.py`：现代 FFmpeg 9.x 滤镜适配
* **修改目标**：解决 `-map_channel` 在现代 FFmpeg（9.x）中已被彻底移除导致的命令报错。
* **具体实现**：
  ```bash
  # 左声道提取
  ffmpeg -y -nostdin -i <source> -af "pan=mono|c0=c0" -c:a flac <audio-left.flac>
  # 右声道提取
  ffmpeg -y -nostdin -i <source> -af "pan=mono|c0=c1" -c:a flac <audio-right.flac>
  ```
* **保留逻辑**：1s 逐块 RMS 能量互补性分析（互补占比 $>25\%$ 且相关系数 $<0.6$ 判为 `split_tracks`）。

---

### 2. `pathology.py`：中文幻觉分级过滤（防假阳性误杀）
* **修改目标**：解决“模板字符串”、“点赞功能”被正则误判为幻觉的缺陷。
* **分级判定规则**：
  ```python
  # 1. 强特征（命中即无条件判定为幻觉排除）
  STRONG_HALLUCINATIONS = re.compile(
      r"(请不吝点赞|明镜与点点|谢谢观看|欢迎订阅|打赏支持|投币|关注本频道|下期再见)",
      re.IGNORECASE,
  )

  # 2. 弱特征（仅当短句且无技术上下文时判定为幻觉）
  WEAK_HALLUCINATIONS = re.compile(r"(字幕|点赞|关注|订阅|转发)", re.IGNORECASE)

  # 3. 技术上下文白名单
  TECH_CONTEXT_WORDS = ("组件", "接口", "功能", "模块", "字符串", "业务", "代码", "设计", "逻辑", "状态")
  ```
* **判定逻辑**：
  * 若命中强特征 $\rightarrow$ 标记排除；
  * 若命中弱特征：若分段文本长度 $< 25$ 字且**不包含**任何 `TECH_CONTEXT_WORDS` $\rightarrow$ 标记排除；否则保留。

---

### 3. `key_transcript.py`：语气分类器防误判与分轨数据注入
* **修改目标**：避免候选人口语化长回答被误划入面试官追问。
* **三级优先级分类逻辑**：
  ```python
  def classify_speech_tone(text: str) -> str:
      t = text.strip()
      if not t:
          return "unknown"

      # 第一优先级：解释性/回答前缀（长度 > 15 字强制为 answer）
      explanation_starters = (
          "其实", "因为", "我们当时", "我这边", "它是", "也就是说",
          "具体来说", "主要是在", "这个其实", "对，我们", "我们是"
      )
      if len(t) > 15 and any(t.startswith(prefix) for prefix in explanation_starters):
          return "answer"

      # 第二优先级：典型追问句式
      q_starters = ("怎么", "为什么", "那你们", "是不是", "对吧", "就假设", "还是", "那你", "那具体", "如何")
      if any(t.startswith(prefix) for prefix in q_starters) or re.search(r"[吗呢吧嘛？\?]$", t):
          return "question"

      # 第三优先级：默认答句
      return "answer"
  ```
* **分轨数据接入**：在 `extract_key_qa_pipeline` 中，当 `is_split_tracks=True` 且存在 `candidate_track_segments` 时，回答窗口内的候选人文本**直接取自候选人轨**，不依赖语气猜测。

### 4. `pipeline.py`：分轨模式贯通与 Turbo 覆盖率自动闭环

#### A. 分轨录音（Multi-Track）全流程支持
* **Stage 2**：检出 `is_split_tracks=True` 时，登记 `audio_asr_track_1` 与 `audio_asr_track_2`。
* **Stage 3（Small 粗转）**：
  * 对 Track 1 粗转 $\rightarrow$ `transcript-full-track1.json`；
  * 对 Track 2 粗转 $\rightarrow$ `transcript-full-track2.json`。
* **Stage 3.5（病理检测与修复）**：分别对 Track 1/Track 2 检测静音与循环病理，合并输出 `transcript-full-track1-merged.json` 与 `transcript-full-track2-merged.json`。
* **Stage 4（问题索引）**：以 Track 1（面试官）为主要输入提取 `question_events`。
* **Stage 5（Turbo 精转）**：
  * Track 1：按选定区间单 clip 精转合并为 `transcript-turbo-merged.json`；
  * Track 2：按 1800s 逻辑分块做全量 Turbo 精转合并为 `transcript-turbo-track2-merged.json`。
* **Stage 6（关键稿生成）**：将 Track 2 Turbo 产物作为 `candidate_track_json_path` 传入。

#### B. Stage 5 问句覆盖率 $\pm 20\text{s}$ 自动校验与补录机制
* **覆盖判定**：遍历 Stage 4 的每个问句事件 $Q_i$，校验在当前 Turbo 合并产物中是否存在未排除的有效段满足：
  $$\text{Turbo.start} \le Q_i.\text{end} + 20\text{s} \quad \text{且} \quad \text{Turbo.end} \ge Q_i.\text{start} - 20\text{s}$$
* **补选区间生成**：
  * 提取所有未覆盖的问句，按时间升序排序；
  * 相邻间隔 $\le 120\text{s}$ 的问句合并为一簇；
  * 补选区间定义为：$[\max(0, \text{Cluster.start} - 10\text{s}), \min(\text{Duration}, \text{Cluster.end} + 60\text{s})]$。
* **自动化执行与版本递增**：
  * 若补录后总覆盖率仍 $\le 40\%$，自动以单命令单区间执行 `transcript-turbo-clip-<N>.json`；
  * 将补充 clip 确定性合并到底稿中，产出 `transcript-turbo-merged-v2.json`。
