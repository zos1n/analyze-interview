# 面试录屏分析

用户输入：$ARGUMENTS

## 第一步：解析输入

- 从参数中提取视频路径（格式可能是"视频路径： xxx/xxx.mp4"或裸路径）
- 若是目录，列出目录内的视频文件让用户确认目标文件
- 若是文件，直接确认

## 第二步：读取执行规范与共享配置并严格遵循

完整规范（唯一执行依据，先完整读取）：
`docs/面试录屏分析工具规范.md`

共享配置（venv 路径 / 解释器 / 镜像 / 阈值 / 词表 / 模型版本，读完规范后立即读取）：
`config/analyzer-config.yaml`

## 核心规则（规范未读到时的底线，读到后以规范为准）

1. **执行前必须获得用户对该录屏的明确读取授权**（只读源文件，禁止修改；允许在产物目录新建文件，共享 venv 目录例外见 config）。未授权前不访问录屏。
2. 记录原视频基线（size + mtime + SHA256），收工后复核一致。
3. **预检先行**：按规范第三节做网络连通性矩阵（pypi.org / 清华镜像 / huggingface.co / hf-mirror.com，curl + Python httpx 双测；共享 venv 不存在时 httpx 检测延后到安装完成后补测，不阻塞预检）和代理检测。
4. **安装审批门**：仅在 FFmpeg/venv/mlx-whisper 缺失或版本不符时触发；先只读核验，全部就绪直接进入阶段 2；有缺失时按规范第四节一次性列出全部缺失项（命令、下载内容、磁盘占用），等用户批准，不拆多次。
5. 每个阶段完成先验证产物再进下一阶段，更新 `execution-state.json` 与 `execution-log.txt`。
6. 粗转/精转后自动跑**转写病理检测**（静音幻觉 / 重复循环 / 时间戳断档），循环幻觉用 `--condition-on-previous-text False` 只重转坏区间。
7. Turbo 精转默认加 `--condition-on-previous-text False`；候选区间覆盖率超 40% 时停止给用户三选项菜单（全程 / 高密度簇 / 手选）。
8. 后台任务必须显式检查退出码（命令后直接跟 `echo "EXIT_CODE=$?"`，不要接管道）。
9. **禁止**：修改原视频、删除产物、修改 .env/密钥/证书、云端视频理解或云端 ASR、完整转写交给分析模型、来源不明下载。失败时停止保留产物，不自动换方案，不从头重跑。
10. 遇规范未覆盖且影响结果的情况，停止向用户说明，不自行决策。
11. 分析阶段（阶段 7）只允许读 `transcript-key.md`，按规范十一节执行；分析器模式（codex / api / self）由用户选择。
12. 最终输出：执行阶段与完成状态、产物绝对路径、转写质量与不确定内容、逐题分析、事实/推断/无法判断三分。

## 稳定环境事实（版本与路径见 analyzer-config.yaml）

- 网络状况（代理端口、pypi/HF 直连）不预设结论，一律以预检实测为准；curl 不读系统代理但 httpx 读，这是双测的原因
- macOS arm64 + Homebrew；Python 用系统 3.9.6（与首次成功执行一致）
- `--output-format` 不支持逗号分隔（用 all）
- Whisper Turbo 有"嗯"重复循环风险，必须用 --condition-on-previous-text=False + 定向重转修复
- 共享 venv 全机一个（config 的 runtime.venv_path），不在产物目录内重建
